# Дневник давления — приложение для iPhone

Личный дневник артериального давления: замеры, принятые лекарства, самочувствие и погода, напоминания о замере и приёме таблеток, обмен данными с приложением «Здоровье».

> **Статус.** Код компилируется в Xcode 26 и запускается в симуляторе iPhone — это проверено сборками на GitHub (вкладка **Actions**). На настоящем iPhone приложение ещё не запускалось: для этого нужна учётная запись разработчика Apple (шаги 3–8). Обмен со «Здоровьем», уведомления и выгрузку в TestFlight можно проверить только на этом этапе.

## Что умеет приложение

| Раздел | Возможности |
|---|---|
| **Дневник** | Верхнее и нижнее давление, пульс, дата и время. К каждому замеру — самочувствие (5 уровней и симптомы), принятые лекарства, погода, заметка. Цветовая категория давления по общепринятой классификации. |
| **Лекарства** | Список лекарств с дозировкой и временем приёма. Отметка «Принять» на сегодня, журнал приёмов. |
| **Напоминания** | Ежедневные уведомления о приёме каждого лекарства и о замере давления — время задаёте сами. Прямо в уведомлении кнопки «Принято», «Записать замер», «Напомнить позже». |
| **Погода** | Температура, атмосферное давление в мм рт. ст., его изменение за сутки, влажность — автоматически на момент замера, по геопозиции или выбранному городу. |
| **«Здоровье»** | Замеры из дневника записываются в «Здоровье» (давление и пульс). Замеры тонометра и других приложений из «Здоровья» появляются в дневнике, к ним можно добавить лекарства, самочувствие и заметку. |
| **Графики** | Давление, пульс и атмосферное давление за 7, 30 и 90 дней, средние значения, сравнение утра, дня и вечера. |
| **Отчёты** | PDF для врача и таблица CSV для Excel. |

Все данные хранятся только на iPhone и в «Здоровье». Серверов и регистрации нет. Требуется iOS 17 или новее.

## Как это попадает на iPhone без Mac

1. Исходный код лежит в вашем репозитории на GitHub.
2. GitHub по кнопке собирает приложение на своём Mac в облаке.
3. Готовая сборка уходит в App Store Connect, откуда ставится на iPhone через TestFlight, а после проверки Apple публикуется в App Store.

Понадобятся: бесплатная учётная запись GitHub и платное участие в Apple Developer Program (99 $ в год). Без платного участия опубликовать приложение в App Store нельзя.

## Шаг 1. Загрузить проект на GitHub

1. Зарегистрируйтесь на <https://github.com>.
2. Установите [GitHub Desktop](https://desktop.github.com) для Windows и войдите в свою учётную запись.
3. Распакуйте архив с проектом в удобную папку, например `Документы\bp-diary`.
4. В GitHub Desktop: **File → Add local repository** → выберите эту папку → программа предложит **create a repository** — согласитесь → **Create repository**.
5. Нажмите **Publish repository**. Галочка **Keep this code private** — на ваш выбор (см. примечание ниже).

Проверьте на сайте GitHub, что в репозитории видна папка `.github` — в ней лежат сценарии сборки.

> **Про стоимость сборок.** Для открытых (public) репозиториев сборки бесплатны. Для закрытых (private) есть ограниченный бесплатный месячный лимит минут, и сборки на macOS расходуют его быстрее обычных. Одна сборка занимает примерно 5–15 минут. Текущий остаток виден в настройках GitHub в разделе Billing.

## Шаг 2. Проверочная сборка (учётная запись Apple не нужна)

На вкладке **Actions** репозитория есть два сценария, которым учётная запись Apple не нужна:

- **«Проверочная сборка»** запускается сама при каждом изменении кода и проверяет, что он компилируется. Зелёная галочка — всё в порядке. Красный крестик — откройте запуск: на странице **Summary** будет блок «Ошибки сборки».
- **«Снимки экрана в симуляторе»** запускается вручную (**Run workflow**). Он открывает приложение в симуляторе iPhone с данными-образцами и складывает снимки всех экранов в ветку `screenshots` репозитория. Занимает около 15 минут.

> **Если запуск долго висит в статусе Queued.** У GitHub два вида Mac, и очередь на один из них бывает длинной. В окне **Run workflow** можно выбрать другую машину в поле «Машина для сборки».

## Установка на один iPhone без учётной записи разработчика

Способ для пробного использования на собственном телефоне. Он бесплатный, но с ограничениями: приложение работает 7 дней, после чего его нужно переустановить с компьютера тем же способом (данные дневника при этом сохраняются, если не удалять приложение с телефона).

1. **Получите файл.** **Actions** → **«Файл для установки на iPhone (IPA)»** → **Run workflow**. Через несколько минут файл `BPDiary.ipa` появится в разделе **Releases** репозитория. Скачайте его на компьютер.
2. **Установите на компьютер** iTunes и программу [Sideloadly](https://sideloadly.io) (бесплатная, для Windows и Mac).
3. **Подключите iPhone кабелем**, на телефоне нажмите «Доверять».
4. **В Sideloadly** перетащите в окно файл `BPDiary.ipa`, укажите свой Apple ID и нажмите **Start**. Программа спросит пароль и код подтверждения.
5. **На iPhone:** Настройки → Основные → VPN и управление устройством → выберите свой Apple ID → «Доверять».
6. **Режим разработчика.** Если приложение не открывается: Настройки → Конфиденциальность и безопасность → Режим разработчика → включить, телефон перезагрузится.

Что учесть:

- Sideloadly — сторонняя программа, и ей передаётся пароль от Apple ID. Многие заводят для этого отдельный Apple ID.
- Обмен со «Здоровьем» при такой установке может не заработать: это зависит от того, выдаст ли Apple бесплатной учётной записи нужное разрешение. Остальные функции от этого не зависят.
- С бесплатным Apple ID одновременно можно держать не больше трёх таких приложений.

Для постоянного использования и для публикации нужен путь через TestFlight — шаги 3–8.

## Шаг 3. Apple Developer Program

Оформляется на <https://developer.apple.com/programs/enroll/> или в приложении Apple Developer на iPhone.

- Как частное лицо — проще и быстрее; в App Store продавцом будут указаны ваши имя и фамилия.
- Как организация (ООО) — потребуется номер D-U-N-S; в App Store будет указано название компании.

Особенности для России (по состоянию на ноябрь 2026 года, условия меняются):

- Регистрация разработчиков из России возможна, бесплатные приложения публикуются.
- Взнос 99 $ картами российских банков и «Мир» не оплачивается. Обычно используют карту зарубежного банка на имя владельца учётной записи либо сервис-посредник.
- Apple может запросить документы для подтверждения личности.

Заложите на этот шаг от нескольких дней до пары недель.

## Шаг 4. Идентификатор приложения

Придумайте идентификатор (Bundle ID) — латиницей, в обратном доменном формате, например `ru.ivanov.davlenie`. Изменить его после публикации нельзя.

1. <https://developer.apple.com/account> → **Certificates, Identifiers & Profiles** → **Identifiers** → **+**.
2. **App IDs** → **App**.
3. **Description** — любое название, **Bundle ID** — **Explicit**, впишите свой идентификатор.
4. В списке **Capabilities** обязательно отметьте **HealthKit**.
5. **Continue** → **Register**.

Там же, на странице **Membership details**, найдите **Team ID** (10 символов) — он пригодится в шаге 6.

## Шаг 5. Приложение и ключ в App Store Connect

**Создать приложение.** <https://appstoreconnect.apple.com> → **Apps** → **+** → **New App**: платформа iOS, название (должно быть уникальным в App Store), основной язык — русский, Bundle ID — выберите созданный в шаге 4, SKU — любой, например `bpdiary1`.

**Создать ключ.** **Users and Access** → **Integrations** → **App Store Connect API** → **Team Keys** → **+**:

- имя любое, доступ (Access) — **Admin**;
- скачайте файл `AuthKey_XXXXXXXXXX.p8` — **он скачивается только один раз**, сохраните его в надёжном месте;
- запишите **Key ID** (рядом с ключом) и **Issuer ID** (над списком ключей).

Этот ключ даёт полный доступ к учётной записи разработчика. Никому его не передавайте и не кладите в репозиторий.

## Шаг 6. Настройки в GitHub

В репозитории: **Settings → Secrets and variables → Actions**.

Вкладка **Secrets** → **New repository secret** (три штуки):

| Имя | Значение |
|---|---|
| `ASC_KEY_ID` | Key ID из шага 5 |
| `ASC_ISSUER_ID` | Issuer ID из шага 5 |
| `ASC_KEY_P8` | Весь текст файла `.p8` (откройте его в «Блокноте» и скопируйте целиком, вместе со строками `BEGIN PRIVATE KEY` и `END PRIVATE KEY`) |

Вкладка **Variables** → **New repository variable** (две штуки):

| Имя | Значение |
|---|---|
| `TEAM_ID` | Team ID из шага 4 |
| `BUNDLE_ID` | Идентификатор приложения из шага 4 |

## Шаг 7. Выгрузка в TestFlight

**Actions** → **«Выгрузка в TestFlight»** → **Run workflow** → **Run workflow**.

Сценарий соберёт приложение, подпишет его и отправит в App Store Connect. Через 10–30 минут сборка появится на вкладке **TestFlight** вашего приложения.

> Этот сценарий тоже ещё не запускался вживую: он требует учётной записи разработчика. Способ подписи взят из работающих открытых проектов, но при первой неудаче пришлите блок «Ошибки» со страницы запуска.

## Шаг 8. Установка на iPhone

1. Установите на iPhone приложение **TestFlight** из App Store.
2. В App Store Connect: **TestFlight** → **Internal Testing** → **+** → создайте группу и добавьте себя.
3. На iPhone придёт приглашение — откройте его в TestFlight и нажмите **Установить**.

Сборка в TestFlight работает 90 дней, обновление — повторный запуск шага 7.

При первом запуске приложение спросит разрешения на уведомления, доступ к «Здоровью» и геопозицию. Проверить связь со «Здоровьем»: добавьте замер, откройте **Здоровье → Обзор → Сердце → Давление** — запись должна появиться с пометкой источника.

## Шаг 9. Публикация в App Store

На странице приложения в App Store Connect заполните:

- **Снимки экрана** для iPhone 6,9″ — подойдут обычные снимки экрана с iPhone 16 Pro Max.
- **Описание, ключевые слова, категория** («Здоровье и фитнес» или «Медицина»). Готовые тексты — в `docs/app-store-listing.md`.
- **URL политики конфиденциальности** — обязателен для приложений, работающих со «Здоровьем». Текст — в `docs/privacy-policy.md`: впишите свои данные и разместите на любой общедоступной странице.
- **URL поддержки** — страница или сайт, где с вами можно связаться.
- **App Privacy** — анкета о данных. Приложение ничего не отправляет на собственные серверы; единственный сетевой запрос — погода, в нём передаются округлённые координаты без какого-либо идентификатора пользователя. Как отразить это в анкете — решение владельца учётной записи.
- **Возрастной рейтинг** — анкета.
- Если App Store Connect спросит, является ли приложение медицинским изделием, — нет, это личный дневник.

Затем выберите сборку и нажмите **Add for Review**. Проверка обычно занимает от одного до нескольких дней.

На что обращает внимание проверка у таких приложений: в описании должно быть прямо сказано про работу со «Здоровьем»; нельзя утверждать, что приложение измеряет давление или лечит; данные о здоровье нельзя использовать для рекламы. В приложении это соблюдено.

## Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| Красная «Проверочная сборка» | Прислать блок «Ошибки сборки» со страницы запуска. |
| `Не задано значение …` | Проверить имена секретов и переменных из шага 6 — они должны совпадать буква в букву. |
| `Invalid authentication key` / `invalidPEMDocument` | В `ASC_KEY_P8` попал не весь текст файла. Вставьте заново, целиком. |
| `No profiles for '…' were found` или упоминание HealthKit в ошибке подписи | У идентификатора из шага 4 не отмечен HealthKit, либо `BUNDLE_ID` не совпадает с ним. |
| Ошибка про cloud-managed certificate или права доступа | Ключ создан не с доступом Admin — создайте новый. |
| `No suitable application records were found` | Не создано приложение в App Store Connect (шаг 5) или выбран другой Bundle ID. |
| Сборка выгрузилась, но не видна в TestFlight | Подождать до получаса; проверить почту — Apple пишет, если сборка отклонена автоматической проверкой. |

## Что стоит знать заранее

- **Погода.** Источник — [Open-Meteo](https://open-meteo.com), ключ не нужен. Бесплатный доступ разрешён для некоммерческого использования; если приложение станет платным или с рекламой, понадобится их платный тариф или другой источник. Погода доступна для замеров не старше трёх месяцев.
- **Лекарства и «Здоровье».** В «Здоровье» передаются только давление и пульс. Лекарства, самочувствие, погода и заметки хранятся в самом дневнике.
- **Удаление приложения** стирает дневник (замеры в «Здоровье» остаются). Перед сменой телефона сделайте резервную копию iPhone или выгрузите CSV.
- **Язык** интерфейса — только русский.
- Пока не сделано: Apple Watch, виджеты, синхронизация между устройствами.

## Устройство проекта

```
project.yml                 описание проекта (из него создаётся проект Xcode)
Config/                     Info.plist и права приложения (HealthKit)
BPDiary/App/                запуск приложения и навигация
BPDiary/Models/             модели данных и статистика
BPDiary/Store/              хранилище дневника
BPDiary/Services/           «Здоровье», уведомления, погода, геопозиция, отчёты
BPDiary/Views/              экраны
BPDiary/Resources/          значок и цвета
.github/workflows/          сценарии облачной сборки
docs/                       политика конфиденциальности и тексты для App Store
```

Если появится доступ к Mac: установите Xcode и XcodeGen (`brew install xcodegen`), в папке проекта выполните `xcodegen generate` и откройте `BPDiary.xcodeproj`.

Приложение — личный дневник. Оно не является медицинским изделием, не измеряет давление, не ставит диагнозов и не заменяет консультацию врача.
